Merchant API reference and integration outline.

Important — not live payment processing.

This version creates payment request records only. It does not collect, settle, or verify real bKash/Nagad/Rocket payments through official provider APIs. Production credentials and approved provider integration are required.

Authentication

Use your approved merchant API key in the X-SojibPay-Key header. Keep it on your server; never put it in public HTML/JavaScript.

X-SojibPay-Key: sp_live_YOUR_KEY

Create payment request

POST /api/v1/payment-requests

curl -X POST https://YOUR-DOMAIN/api/v1/payment-requests \
  -H 'Content-Type: application/json' \
  -H 'X-SojibPay-Key: sp_live_YOUR_KEY' \
  -d '{"amount":250,"description":"Order #1001","reference":"order_1001"}'

Example response:

{
  "payment": {
    "public_id": "spay_example",
    "amount": "250.00",
    "currency": "BDT",
    "status": "pending"
  },
  "checkout_url": "https://YOUR-DOMAIN/checkout.html?id=spay_example",
  "note": "Checkout requests are records only until an approved payment provider is integrated."
}

Checkout record lookup

GET /api/checkout/:publicId returns the payment request status and merchant display name. In this starter, the checkout is a reference page, not a provider-hosted payment page.

Production integration checklist

  • Approved payment provider API credentials and merchant onboarding.
  • Provider callback signature validation and idempotency.
  • Server-side amount/order matching and reconciliation.
  • Signed webhooks with retries and event logs.
  • Refund, dispute, audit and incident-response procedures.
